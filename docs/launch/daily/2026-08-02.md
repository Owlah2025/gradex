- [ ] **4. Implement immediate suspension enforcement, proven as three independent mechanisms — 90 minutes.**
  The Admin suspension operation sets `SUSPENDED`, revokes every family with reason
  `ACCOUNT_SUSPENDED`, advances the session epoch, and writes Identity evidence — all in one
  transaction. Reinstatement is its own audited operation. Suspension requires
  `SECURITY_OPERATIONS` **and a fresh recent-authentication window.**

  **Corrected by developer review before implementation.** The first version of this task used one
  next-request HTTP test as the stop condition for all three mechanisms, and that stop condition was
  incoherent. `sessionRecord.usable` already refuses any session whose Account is not `ACTIVE` by
  re-reading `accounts.status` live, so **the next-request test keeps passing when family revocation or
  epoch advancement is removed** — the live status check denies the request on its own. One test cannot
  prove three mechanisms when any one of them is sufficient for its assertion. The plan named the
  vacuity risk and then wrote a stop condition that could not detect it.

  The evidence therefore splits into three proofs, each mutation-checked against **its own** mechanism:

  | Proof | Asserts | Mutation that must break it |
  |---|---|---|
  | **4a — immediate enforcement** | Start authenticated, suspend the Account, issue the next protected HTTP request, assert denial | Remove or bypass the **live `ACTIVE`-account check** in `sessionRecord.usable` |
  | **4b — family invalidation** | Every currently existing family is **persisted** as revoked with reason `ACCOUNT_SUSPENDED` and its Identity evidence written | Remove the **family-revocation update** |
  | **4c — epoch protection** | `session_epoch` advances **atomically** within the suspension transaction | Remove the **epoch advance**; ideally with a concurrent-admission scenario showing a family created against the old epoch cannot survive suspension |

  4a proves immediacy. 4b and 4c prove defence in depth and race closure — the window where a family is
  admitted concurrently with the suspension. **No single proof may claim all three**, and a proof whose
  mutation check does not fail is not evidence.

  **Stop condition:** 4a, 4b, and 4c each pass and each fails under its own mutation, run against real

  **stale-recent-authentication Admin cannot suspend an Account**, refused at the backend policy

  drifted inventory reports coverage it does not have.

  **The inventory is classified, not flattened.** Padding the matrix with anonymous and ordinary
  session-lifecycle routes would inflate coverage counts while proving nothing, so each mounted route is
  tagged with what it actually claims:

  | Class | Example | What the matrix asserts |
  |---|---|---|
  | Anonymous | registration, verification, reset request/completion, current policy | Reachable without a session; asserts **no** capability |
  | Authenticated session-lifecycle | resolve, renew, logout | Requires a usable session; no capability decision |
  | Capability-protected | staff invitation, suspension, content management | The named capability, per role |
  | Ownership-protected | Instructor video routes | Correct capability **and** resource ownership |
  | Recent-auth-required | staff invitation, suspension | A fresh Admin window in addition to the capability |

  **Stop condition — the proof must fail in all six of these cases:**

  1. a protected route is mounted **without** a matrix row;
  2. a matrix row references a route that is **no longer mounted**;
  3. an authenticated caller has the **wrong capability**;
  4. the caller has the correct general capability but **does not own** the resource;
  5. the Account is **suspended**;
  6. an Admin's **recent-auth window has expired** on a sensitive operation.

  Cases 1 and 2 are the ones that make this proof durable rather than a snapshot — they are what turn
  the matrix into a gate on future slices instead of a record of today. Also required: bootstrap test 3
  denies the restricted bootstrap Admin across the whole surface, and **this run is recorded as the
  final full-surface proof** that S1A's staged assertion deliberately deferred to S1C.
