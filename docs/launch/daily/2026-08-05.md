### Retention blocker — and the infrastructure added to close it

T075's verb is **Retain**, at the S2 T066 standard. [`STATUS.md`](../STATUS.md) recorded that
standard as "the retained HTML report is the configured CI artifact, while traces remain
failure-only by policy". The repository did not implement it:

- `.github/workflows/ci.yml` had **no Playwright job**. Its `frontend` job runs `lint`, `typecheck`,
  `test`, and `build` only.
- `.github/` contained **no `actions/upload-artifact` step anywhere**, so there was no configured CI
  artifact for a report to be.
- `frontend/.gitignore` excludes `playwright-report/` and `test-results/`.
- `git ls-files` tracks **zero** images and no evidence directory.

So the documented convention was false, and every candidate destination was transient. That gap has
now been closed as repository infrastructure rather than worked around.

**Added:** an `S5 T075 Rendered Evidence` job in `ci.yml`. It brings up PostgreSQL and Redis as
service containers — no MinIO, because the shared E2E setup already points `S3_ENDPOINT` at the
run-owned local media fixture server it starts itself — installs from the lockfile, installs the
lockfile-pinned Chromium, and runs **only** `frontend/e2e/s5-viewport-evidence.spec.ts`. The existing
`global-setup`/`global-teardown` are reused unchanged for service lifecycle: they compile the API and
seeder to external output paths, create and seed an isolated per-run database, start the media server
and API, and tear all of it down even when the run fails. No startup logic was duplicated into YAML.

Three transient-path bases became environment-overridable, each keeping its current value as the
default so every existing suite is unaffected when unset:

| Variable | Purpose |
|---|---|
| `GRADEX_E2E_TMP_DIR` | base for the compiled binaries, lock, run state, and drained API log — CI points it at the job temp directory |
| `GRADEX_T075_EVIDENCE_DIR` | where the 32 PNGs are written |
| `GRADEX_PLAYWRIGHT_HTML_DIR` | where the HTML report is written |

**Artifact.** One directory is uploaded, named `gradex-s5-t075-rendered-<commit sha>` — deterministic
and commit-associated. A failing run uploads under `gradex-s5-t075-rendered-FAILED-<commit sha>`
instead, so a diagnostic upload can never be read as retained evidence. `if-no-files-found: error` on
the passing path. Retention duration is the repository default; none is invented here. Trace archives
are excluded from the upload by design: they are compressed, so the audit cannot inspect them, and an
unauditable archive should not be published. Traces remain failure-only on the runner.

**Manifest, integrity, and audit.** `frontend/scripts/t075-evidence-manifest.mjs` — following the
existing `frontend/scripts/*.mjs` convention, no new dependency — runs in three modes before upload:

- `generate` writes `manifest.json`: schema `gradex.t075.rendered-evidence/1`, commit SHA, workflow
  run id and attempt, UTC generation time, Playwright and Chromium versions, spec filename, expected
  and actual cell counts, the HTML report's path/size/SHA-256, and one entry per screenshot with
  path, screen, locale, direction, viewport, width, height, byte size, and SHA-256. It records no
  fixture UUID, Account id, session id, report context, cookie, CSRF or bearer token, signed URL, or
  connection string.
- `verify` re-derives the 32-cell matrix from SC-010 rather than describing whatever it finds, then
  fails on a missing cell, an unexpected cell, a duplicate cell, an invalid PNG, a width that does
  not match its viewport, two cells resolving to byte-identical files, a missing HTML report, a
  report with no embedded payload, a size or digest disagreement, or a manifest entry pointing at a
  nonexistent file.
- `audit` refuses the upload on credential-shaped **values** — `Set-Cookie`, a `__Host-` cookie
  assignment, a cookie header with a value, a bearer token, a PostgreSQL or Redis DSN carrying
  credentials, an `X-Amz-Signature` or signed playback query parameter, Playwright storage state, a
  private-key block — and on forbidden filenames (`.env*`, storage-state JSON, secrets files). It
  deliberately does **not** fail on field *names*: the detector's own assertion titles say "must not
  contain report_context", and failing on that would make the audit unusable and switched off. It
  reports the pattern and byte offset, never the matched value.

Each guard was proved non-vacuous locally rather than assumed: a removed cell, a duplicated image, a
deleted HTML report, and a corrupted PNG each turned `verify` red with a named message and exit
status 1, while the clean set exits 0; a planted `Set-Cookie` line and a planted PostgreSQL DSN each
turned `audit` red, and the clean set passes.
