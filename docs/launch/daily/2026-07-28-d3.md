#### OD-001 — recorded as an open developer decision, not resolved

[§2.2](../AUGUST_15_EXECUTION_PLAN.md#22-reduced-slices--launch-critical-core-retained-remainder-reclassified)
defers "Arabic-normalized ranked search" to post-launch as **one item**. It bundles two things with
very different costs:

- **Ranking** is genuinely optional at 8–12 Courses. Deferring it is sound.
- **Arabic normalization** is not a ranking feature. It is what makes matching work at all in the
  product's default language. Without alef/hamza folding, a visitor searching `احياء` does not match a
  Course titled `أحياء`.

The failure mode is not "results are ordered badly" — it is "the search box returns nothing for a
correctly spelled query", on an Arabic-default platform, for most real queries. Recommendation is to
pull normalization into S3 (~2–3h of an 8h slice) and keep ranking and filtering deferred. **If the
deferral stands, FR-023 must be weakened and the spec must stop claiming BR-162 compliance** rather
than shipping a search box that fails silently in Arabic.

Recorded as `OPEN` in [spec.md](../../../specs/004-public-catalogue/spec.md#resolved-decisions), and
**resolved `ADJUST` by the developer the same day** — see the reconciliation below.
