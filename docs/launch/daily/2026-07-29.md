## Must

The bootstrap chain is ordered and each link depends on the one above it. It cannot be worked out of
sequence — see [SLICES.md §5.1](../SLICES.md#51-bootstrap-chain--fixed-order).

- [ ] **1. Bootstrap schema and state.** Accounts with immutable role, password credentials, an
  explicit Identity-owned constrained `PASSWORD_CHANGE_REQUIRED` marker that does not overload
  `accounts.status`, and a dedicated bootstrap singleton/completion record that does not reuse
  shared `idempotency_records` as domain uniqueness.
- [ ] **2. Controlled one-off bootstrap command.** Its own `cmd/` entrypoint, not an HTTP endpoint,
  ordinary worker, or schema migration.
- [ ] **3. Restricted bootstrap-session policies.** Deny-by-default typed authorization permitting
  only password change and session termination.
- [ ] **4. Mandatory password-change completion.** Normal recent-authentication rules and Argon2id.
- [ ] **5. Session rotation and restriction removal.** Atomic: neither half may land alone.
- [ ] **6. Normal Admin authorization.** Further Admins only through the invitation workflow.
- [ ] **7. Registration, verification, login, refresh rotation, logout, and recovery** with
  non-enumerating responses per the §5 privacy boundary.
- [ ] **8. Staff invitations and immediate suspension enforcement** across new and existing sessions.

## Bootstrap close conditions

S1 does not close until all five pass. Test 3 must assert against real protected endpoints, not a
policy function in isolation, or it proves nothing about the deny path.

| # | Proves |
|---|---|
| 1 | Bootstrap cannot complete twice — same operation ID, different ID, or concurrent. |
| 2 | The plaintext bootstrap password is never persisted, logged, written into a migration, placed in process arguments, or emitted to telemetry. |
| 3 | The bootstrap Admin cannot call unrelated protected APIs before changing its password. |
| 4 | A successful password change atomically clears the requirement and rotates the Session. |
| 5 | Failure midway leaves neither a second usable Admin nor a falsely completed bootstrap marker. |
