## Source-address ceiling — why 600 / 10 min

No requirement fixes this number, so it was selected in this pass rather than invented silently. Full
rationale in D-071; the three constraints were: no ordinary Student can exhaust it (a Student spending
their full 30 consumes 5% of it), it survives a real shared campus egress address (~100 concurrent
learners at ~6 issuances / 10 min under D-061's population assumption), and it still caps sustained
scripted extraction at one issuance per second. It stays a separate policy with a separate key, because
merging it would let one heavy Student consume a shared address's headroom or let a NAT population mask a
single extracting account.

## A defect found in my own H-1 work

The first draft of the two playback policies set `LocalMaxKeys: 8192` but omitted `FailClosed: true`. That
made an undecidable ceiling fall through to the in-process local limiter, which *allowed* — so a
rate-limit dependency failure would have permitted issuance, which is precisely what FR-017 forbids and
what H-1 was about. The fail-closed test caught it, and the fix was in production code, not in the test.
Recorded because the failure mode is easy to reintroduce: on this limiter, fail-closed behaviour comes
from `FailClosed`, and a local fallback is not a safe substitute for a shared quota decision.

## Hosted CI caught what my local validation did not

Run [31070393404](https://github.com/Owlah2025/gradex/actions/runs/31070393404) on head `b1190f0`
returned **failure**: five jobs green — Migrations, Backend, Guards, S5 T075 Rendered Evidence,
Frontend — and **`Admission Integration` failed** at the `Admission migration and transaction evidence`
step. Job logs require admin rights on this repository and the check annotation carried only
`Process completed with exit code 1`, so the cause was found by reproducing the exact hosted command
locally rather than by reading the log.

The cause was **my own H-1 change, not the M-1 addition.** Three places assemble the protected-learning
policy map independently — `backend/cmd/api/main.go`, the `!production` test helper, and the integration
fixture in `backend/internal/httpapi/learning_progress_integration_test.go` — and
`NewLearningFoundation` refuses to construct unless every endpoint in `requiredLearningPolicyEndpoints`
is present. I added the two playback endpoints to the first two and missed the third, so every
`internal/httpapi` integration test that builds the production foundation failed with
`required learning endpoint policy "learning-playback-source" is missing`. The failure would have
happened with or without M-1.

**Why my local validation missed it.** `go test -race ./...` runs *untagged* tests, and
`go vet -tags=integration ./...` compiles the integration files without executing them. Neither
executes an integration test. I had also run `./internal/learning` alone, which passes. The gap was
never running the hosted command itself. Corrected — the exact hosted command now runs locally:

```text
go test -tags=integration ./internal/identity ./internal/outbox ./internal/httpapi \
  ./internal/catalogpublic ./internal/ratelimit ./internal/learning
→ ok identity 95.5s · outbox 2.3s · httpapi 185.8s · catalogpublic 1.4s · ratelimit 0.02s · learning 42.9s
```

The underlying duplication — one required-endpoint list against three independently maintained policy
maps — is a real defect that will break again on the next added endpoint. Consolidating it needs a new
exported production constructor, which is outside this pass's authorized scope, so it is recorded in
D-071 as open rather than fixed silently.
