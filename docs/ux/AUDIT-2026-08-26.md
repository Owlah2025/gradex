## 2. Actual course workflow map (traced from code)

| Step | Route / component | API | State |
|---|---|---|---|
| Instructor creates course | `course-builder.tsx:228` `createCourse` | `authoring.ts` | course `DRAFT`, revision `DRAFT` |
| Instructor edits | `course-builder.tsx` (details, sections, lessons, uploads) | `authoring.ts` | revision `DRAFT` |
| Instructor submits | `course-builder.tsx` submit | `authoring.ts` | revision `PENDING_REVIEW` |
| **Admin discovery** | `/[locale]/admin/catalog` → `review-queue.tsx:40` | `GET /admin/review/queue` | lists `PENDING_REVIEW` revisions only |
| Admin opens review | in-page state `setInspectedItem` → `submitted-revision-inspector.tsx` | `GET /admin/review/courses/:id/revisions/:rid` | — |
| Admin assigns taxonomy | `taxonomy-override-form.tsx` (inside inspector) | `PUT /admin/courses/:id/taxonomy` | — |
| Admin sets price | `pricing-panel.tsx` → `pricing-form.tsx` (inside inspector) | `PUT /admin/courses/:id/price`, `/sections/:sid/price` | — |
| Admin decides | inspector | `POST .../approve`, `POST .../request-changes` (reason mandatory) | approved → live revision; changes → `CHANGES_REQUESTED` |
| Instructor sees result | `change-request-notice.tsx`, `revision-workflow-panel.tsx`, `revision-workflow.ts` | `getOwnedCourses` | `EDIT_CANDIDATE` / `CANDIDATE_IN_REVIEW` / `START_REVISION` / `UNAVAILABLE` |
| Lifecycle ops | `/[locale]/admin/course-lifecycle` | `GET /admin/courses`, `POST /admin/courses/:id/{delist,relist,retire,archive}` | `PUBLISHED`/`DELISTED`/`ARCHIVED` + retired/suspended |
| Access grant | `/[locale]/admin/course-access` | invitations, expiry | published only |
| Student access | `/[locale]/access`, `/learn/*` | `learning.ts` | — |

### Root cause of the reported UUID-copying failure

The lifecycle is **discontinuous at exactly one point**: Admin course discovery is keyed to
`PENDING_REVIEW` and nothing else.

- The review queue (`GET /admin/review/queue`) returns *only* submitted revisions. A `DRAFT`
  course — the state a course is in immediately after an Instructor creates it — appears nowhere in it.
- The only Admin surface that lists courses in **every** state is the lifecycle directory, but it is
  presented as *"Course Lifecycle & Emergency Controls"* and offers only delist / relist / retire /
  archive / suspend / restore. It has no route to metadata or pricing.
- `/admin/course-access` is published-only (`published-course-selector.tsx`: *"No published Courses
  are available yet"*).
- Per-course taxonomy and pricing assignment exist **only** inside `SubmittedRevisionInspector`,
  i.e. reachable only for a `PENDING_REVIEW` course, and only via in-page state — there is no route
  to a specific course's review screen.

So an Admin looking for a just-created course finds an empty queue and no other course-shaped
surface, and falls back to reading the id off another screen. The Instructor studio hands it to
them: `instructor/server-pricing-panel.tsx:140` renders the raw course UUID under each course title
in `font-mono`, and `:186` renders raw section UUIDs.

**The backend already solved this.** `catalog/lifecycle_directory.go:14` states the intent
verbatim — the directory row carries *"enough human-readable identity to take it without handling a
UUID"* — and `GET /admin/courses?q=` returns every course in every lifecycle state
(`DRAFT | PENDING_REVIEW | CHANGES_REQUESTED | PUBLISHED | DELISTED | ARCHIVED`) with
`owner_display_name`, titles in both languages, suspension/retirement stamps and `updated_at`,
ordered by `updated_at DESC`, limit 50, searchable by title. The frontend simply never mounted it as
a Courses surface.

**No backend change is required to fix this.**

## 3. Actual anonymous / student personalization workflow map

| Step | Reality |
|---|---|
| Visitor opens `/` | Marketing sections. No academic prompt, no university/major entry point. |
| Selects university | Only inside `/[locale]/catalog` via `academic-filters.tsx`, presented as *"Filter by study plan"*. |
| Selects program/level/subject | Same panel; dependent options cascade correctly (`applySelection` clears children). |
| Personalized catalogue | Works. `getPublicCourses(locale, q, filters)`. |
| Persistence | **URL query string only** (`academic-filter-state.ts`). No storage. |
| Course detail | `/[locale]/catalog/[slug]` — the link carries **no selection**. |
| Back | Browser Back restores the URL. But the detail page's own header link goes to bare `/[locale]/catalog`, **dropping the selection**. |
| Signup | Selection is not carried into `/register` in any form. |
| Account association | `learn/academic-profile` exists but is a separate, from-scratch form. |

### Existing capabilities relevant to university/major persistence

**Anonymous (`lib/api/public-catalog.ts`, all unauthenticated, keyed by slug):**
- `getPublicInstitutions()` → `{slug, name_ar, name_en}`
- `getPublicPrograms(institutionSlug)` → `{slug, name_ar, name_en, college_name_ar, college_name_en}`
- `getPublicLevels(...)`, `getPublicSubjects(...)`
- `getPublicCourses(locale, q, {institution, program, level, subject, relevantToProgram})`

**Authenticated (`lib/api/academic-profile.ts`, keyed by UUID):**
- `getAcademicProfile()` → `{setup_state, institution_id, program_id, program_slug, ...}`
- `listInstitutionOptions()` → `{id, name_ar, name_en, max_academic_level, has_foundation_stage}`
- `listCollegeOptions(institutionID)`, `listProgramOptions(institutionID, collegeID)`
- `saveAcademicProfile({institutionID, enrollmentStatus, programID, academicUnitID, currentLevel})`
- `skipAcademicOnboarding()`, `shouldPromptOnboarding()`

### The binding gap — precise statement of the missing mapping contract

The two option sets are keyed differently and share no stable identifier.

| | Anonymous (`/catalog/academic-options/…`) | Authenticated (`/me/academic-options/…`) |
|---|---|---|
| Institution | `slug`, `name_ar`, `name_en` | `id` (UUID), `name_ar`, `name_en`, `max_academic_level`, `has_foundation_stage` |
| College | *not exposed*; only `college_name_ar/en` denormalized onto a program | `id` (UUID), `name_ar`, `name_en` |
| Program | `slug`, `name_ar`, `name_en`, `college_name_ar/en` | `id` (UUID), `name_ar`, `name_en`, `department_name_ar/en` |
| Profile write | — | `PUT /me/academic-profile` requires `institution_id`, `program_id`, `academic_unit_id` (**UUIDs**) |

The public side never emits a UUID; the authenticated side never emits a slug. The **only**
overlapping values are localized display names, which are not identifiers: they are not guaranteed
unique, they are locale-dependent, and they are editable through Admin academic-catalog management.

**Joining the two by display name is rejected as a production mechanism.** It would make an
account's academic profile depend on Arabic/English string equality, and an ordinary Admin rename
would silently bind a Student to the wrong Program.

**Precise missing contract.** Exactly one of the following would close the gap; none exists today:

1. `slug` added to the authenticated option payloads (`InstitutionOption`, `ProgramOption` under
   `/me/academic-options/…`) — the smallest change, and symmetric with `AcademicProfile.program_slug`,
   which the profile **read** already exposes; or
2. a resolve endpoint, e.g. `GET /me/academic-options/resolve?institution_slug=…&program_slug=…`
   returning the corresponding UUIDs; or
3. acceptance of slugs on `PUT /me/academic-profile` alongside the existing UUID fields.

Note the asymmetry that makes (1) natural: the profile **read** already returns `program_slug`, so
the server can map program UUID → slug. Only the reverse direction is unavailable to the client.

**Tranche C design under the current contract (no backend change):**

- Persist the anonymous selection using the **stable public identifiers the catalogue already
  emits** — institution slug, program slug, level, subject code — never display names, never UUIDs.
- These slugs are already the catalogue's shareable URL vocabulary (`academic-filter-state.ts`), so
  personalization stays consistent across visit, refresh and shared link.
- After authentication, **do not** auto-write the profile and **do not** claim account binding.
  Show the remembered choice as named context ("You were browsing *Kuwait University · Computer
  Science*") and let the Student confirm their academic profile through the **real authenticated
  options**, which is the only place the correct UUIDs exist.
- Preselection happens **only** if a deterministic, stable mapping becomes available (option 1, 2 or
  3 above). Until then the Student's confirmation is an explicit selection, not a silent join.

This keeps the pre-signup experience fully functional and honest, and isolates the one backend
change that would upgrade "confirm" into "preselect" — to be raised for approval separately, not
made inside a frontend tranche.

## 3a. Verified lifecycle prerequisite contract (read from `backend/`, unmodified)

Checked before designing Tranche A navigation, to rule out a circular dependency.

| Concern | Owner | Required for | Route |
|---|---|---|---|
| Academic identity — `LEGACY_TAXONOMY`: major + subject + study year | **Instructor** | **Submission** | `PATCH /courses/:id/revisions/:rid` |
| Academic identity — `ACADEMIC_CATALOG`: institution + subject | **Instructor** | **Submission** | subject-first authoring |
| Taxonomy **override** | Admin | never required | `PUT /admin/courses/:id/taxonomy` |
| **Launch price** | **Admin** | **Approval only — explicitly not submission** | `PUT /admin/courses/:id/price` |

Evidence:
- `validation.go:156-194` — submission fails with `TAXONOMY_DIMENSION_MISSING` for MAJOR, SUBJECT and
  STUDY_YEAR; `validation.go:211-229` — `ACADEMIC_INSTITUTION_MISSING` / `ACADEMIC_SUBJECT_MISSING`.
  All are Instructor-writable fields.
- `review.go:369-372` states the rule verbatim: *"Publication, unlike Instructor submission,
  additionally requires the Admin-owned launch price (BR-019). It is checked here rather than in
  `validateCourseForSubmission` because an Instructor can never satisfy it: only Admins set prices,
  so submission must not demand one."* Violation code `COURSE_PRICE_REQUIRED`.
- `taxonomy.go:255-260` — the Admin override is **refused for `ACADEMIC_CATALOG` courses**; their
  Subject is corrected by the Instructor through Request Changes.
- `pricing.go:145-157` — "has launch price" is the existence of a `course_price_changes` row with
  `section_id IS NULL`. Readable from the frontend via `getCoursePriceHistory` (a course-level
  record is one with no `section_id`).

**There is no circular dependency.** The order is: Instructor assigns academic identity → Instructor
submits → Admin sets the launch price → Admin approves. **An Admin is never required to configure
anything before submission**, so a `DRAFT` course requires no Admin action and must not appear in
"Needs review".

Consequently **"Needs review" is defined as membership in `GET /admin/review/queue`, not as
`lifecycle === "PENDING_REVIEW"`.** These differ in a real case: an Instructor revising an
already-published course produces a `PENDING_REVIEW` *revision* while the *course* lifecycle stays
`PUBLISHED`. Deriving the queue from lifecycle would hide exactly that course from review. The
existing review-queue model is preserved unchanged; the directory is an additional discovery
surface over `GET /admin/courses`.

## 4. Highest-severity findings

### P0 — blocks MVP operation

**P0-1. An Admin cannot reach a course that is not `PENDING_REVIEW`.**
No Admin surface lists courses by state with a route to act on them. A `DRAFT` or
`CHANGES_REQUESTED` course is invisible to Admin except through the emergency-controls list, which
cannot assign metadata or pricing. This is the reported production failure.
`review-queue.tsx`, `course-lifecycle-workspace.tsx`, missing `/admin/courses`.

**P0-2. The review workspace has no route.**
`SubmittedRevisionInspector` mounts from `useState` inside `ReviewQueue`. There is no
`/admin/courses/<id>/review` URL, so a review cannot be linked, bookmarked, refreshed, or returned
to with Back. Refreshing mid-review loses the entire context. `review-queue.tsx:177`.

### P1 — severe production UX failure

**P1-1. Raw UUIDs rendered to users.**
`instructor/server-pricing-panel.tsx:140` (course id), `:186` (section id),
`app/[locale]/admin/course-access/page.tsx:585` (invitation id). This is the clipboard source for
the reported workflow.

**P1-2. Raw backend enums rendered as status.**
`course-lifecycle-workspace.tsx:311` — `lifecycleLabel` puts `course.lifecycle` on screen verbatim
(`DRAFT`, `PENDING_REVIEW`, `CHANGES_REQUESTED`). No explanation, no next action, no owner.

**P1-3. An entire Admin screen is English-only.**
`app/[locale]/admin/course-access/page.tsx` — 998 lines, **0 Arabic characters**, despite importing
`useLocale`. Same for `admin/published-course-selector.tsx`. In Arabic the app renders `dir="rtl"`
with English strings.

**P1-4. Course detail uses a different application shell than the rest of the product.**
`CatalogueDetail`'s local `Shell` (`public-catalogue.tsx:141`) has its own header, its own language
toggle, its own skip link, no `Navbar`, no `Footer`, and hardcodes `bg-slate-50 text-slate-950` —
which **defeats dark mode entirely** on that page. Navigating list → detail changes the whole chrome.

**P1-5. No pre-signup academic personalization surface.**
Selection is buried inside the catalogue as *"Filter by study plan"* and is never offered on the
landing page.

**P1-6. Academic selection is lost on ordinary navigation.**
Detail links drop the selection; the detail header's catalogue link returns to an unfiltered
catalogue. Nothing survives a fresh visit.

**P1-7. Three different page chromes.**
(a) marketing/catalogue-list: `Navbar` + `Container` + `Footer`; (b) admin/instructor:
`RoleWorkspaceShell`; (c) learning + catalogue detail: bare `<main>` with a bespoke locale toggle
and **no global navigation at all**. A Student on `/learn/dashboard` has no logo, no catalogue link
and no sign-out.

**P1-8. Status presentation is unshared.**
`LearningStatusBadge` (learning), inline `<span>` pills (review queue), `lifecycleLabel` string
concatenation (lifecycle), a hardcoded green `PUBLISHED` pill (`published-course-selector.tsx:96`),
and `Badge` (design system) all solve the same problem independently.

### P2 — meaningful usability problems

- **P2-1. Design-system drift.** `Never hardcode a hex in a component` is the stated rule

## 5. Responsive risks
- `review-queue.tsx` table: `overflow-x-auto` only — a 5-column table with no mobile representation.
- `app/[locale]/admin/course-access/page.tsx`: wide tables, invitation ids in cells.
- `course-lifecycle-workspace.tsx`: `flex-wrap` rows of 4+ buttons plus a 3-column control grid;
  cramped under 768.
- `course-builder.tsx`: `lg:flex-row` forms; the single-screen studio at 390 is a very long scroll.
- Course detail is `max-w-4xl` single column at every width — 1440 desktop space is unused, and the
  access CTA sits below the full curriculum.

## 6. RTL risks
- Course detail's `Shell` sets `dir` but the page hardcodes light-only colours and a bespoke header.
- Admin/instructor screens set `dir` at `<html>` via `LocaleProvider` but are laid out with
  `justify-between`/`flex` assumptions never verified in Arabic.
- `LocaleProvider` deliberately ignores the path locale for `/en/admin/*`, so an Arabic-language
  admin session renders at an `/en/...` URL — confusing but intentional.
- Chevron/direction semantics unverified for the curriculum accordion and lesson prev/next.

## 7. Accessibility risks
- Status conveyed by colour + raw enum text with no accessible description (P1-2).
- `course-lifecycle-workspace.tsx` destructive actions (Archive, Retire, Suspend) have **no
  confirmation step** — single click, irreversible-by-design operations.
- Admin tables lack caption/scope semantics.
- Focus management on inspector open/close is unhandled — the inspector is inline, not a dialog, and
  focus is not moved to it.
- Good baseline elsewhere: `SkipLink`, `focus-visible` rings on design-system components,
  `role="alert"`/`role="status"` used consistently in admin surfaces.

## 8. Course Detail gaps
Available real fields (`PublicCourseDetail`): `title`, `instructor_display_name`, `description`,
`university`, `major`, `subject`, `study_year`, `price{minor_units,currency}`, `has_preview`,
`sections[{title, position, lesson_count}]`, `program_audience[]`.

**Not available — must not be invented:** ratings, review counts, enrolment counts, durations,
lesson titles, last-updated, language, learning objectives, prerequisites, instructor bio/credentials.

Gaps: no breadcrumb or back-to-catalogue; access CTA below the entire curriculum; description
rendered as one undifferentiated block; no use of desktop width; hardcoded teal
(`bg-teal-800`, `text-teal-800`) instead of `primary`; dark mode broken; taxonomy chips render
before the title, so the first thing read is metadata rather than the course.

## 9. Admin / Instructor lifecycle gaps
Summarized in P0-1, P0-2, P1-1, P1-2. Additionally: the Instructor has no single place showing
"what is incomplete" before submission; `CHANGES_REQUESTED` reason display exists
(`change-request-notice.tsx`) but is inside the one large studio screen; the Admin has no way to see
a course's *history* of decisions outside price history.
