# S1B1 Student Admission Data Model

**Status**: Phase 1 design
**Scope**: Student registration, verification request/resend, verification consumption, and the
three S1A admission hardening fixes

The authoritative relational state is PostgreSQL. Redis contains only disposable limiter entries.
Names below are the planned logical schema; the versioned migration is
`0005_student_admission`.

## Existing entity changes

### Account

Existing table: `accounts`.

| Field | S1B1 rule |
|---|---|
| `id` | Opaque UUID primary key. |
| `normalized_email` | Trimmed, case-folded comparison key; globally unique. |
| `email` | Trimmed correspondence address preserving the supplied casing; never used as the uniqueness key. |
| `role` | Public registration writes `STUDENT` only; role remains immutable. |
| `status` | Registration writes `PENDING_VERIFICATION`; successful verification alone transitions it to `ACTIVE`. |
| `display_name` | Non-unique BR-105 label: 2–50 Unicode code points, Arabic/Latin script, no URL, control character, or markup. |
| `locale` | `ar` or `en`, used for the delivery snapshot and UI. |
| `email_verified_at` | Null while pending; database time on activation. |
| `revision` | Incremented exactly once on successful activation. |

Relationships:

- One Account has one password credential.
- One Account has many immutable policy acceptances.
- One Account has many historical action secrets, with at most one live email-verification secret.
- One Account may be referenced by many Identity security events and outbox events.

State transition:

```text
PENDING_VERIFICATION --valid live EMAIL_VERIFICATION secret--> ACTIVE
```

No S1B1 command transitions an Active or Suspended Account.

### Password Credential

Existing table: `password_credentials`.

S1B1 writes one `ACTIVE` Argon2id credential for a newly registered Account. Password plaintext
exists only inside `identity.prepareCredential`; only the PHC hash reaches this table. The required
compromised-password source must answer before hashing succeeds. Existing normalized-email no-op
creates no credential.

### Bootstrap Operation

Existing table: `bootstrap_operations`.

Add:

| Field | Type | Rule |
|---|---|---|
| `fingerprint_version` | small integer, nullable only for a pre-0005 legacy row | Positive when present. |
| `request_fingerprint` | 32-byte digest, nullable only for a pre-0005 legacy row | Versioned digest of canonical non-secret semantics. |

The two fields are both null or both present. A new operation always supplies both. A same-ID retry
must:

1. compare the submitted canonical fingerprint in constant time;
2. verify the supplied password against the recorded Argon2id credential;
3. return the recorded result only when both match.

A legacy row without a fingerprint, changed field, changed password, or password changed since the
original bootstrap fails closed. The fingerprint never contains plaintext or a fast password
digest.

## New relational entities

### Policy Acceptance

Table: `policy_acceptances`.

Immutable evidence that the registrant accepted an exact policy version shown as part of one
server-recognized policy set.

| Field | Type | Constraints |
|---|---|---|
| `id` | UUID | Primary key, generated by PostgreSQL. |
| `account_id` | UUID | Required FK to `accounts`; cascade only with future approved Account deletion. |
| `policy_set_id` | text | Required opaque versioned set ID; bounded and nonblank. |
| `policy_kind` | text | Required constrained identifier such as the resolver-provided privacy/terms kind; uppercase token format. |
| `policy_version` | text | Required bounded nonblank immutable version. |
| `locale` | text | `ar` or `en`; language of the displayed acceptance. |
| `accepted_at` | timestamptz | Required database time. |
| `request_id` | text | Required safe correlation identifier; not an idempotency or identity key. |

Constraints/indexes:

- unique `(account_id, policy_kind, policy_version)`;
- index `(policy_kind, policy_version, accepted_at)`;
- append-only trigger rejects UPDATE/DELETE.

The required policy kinds and public links are supplied by a `PolicySetResolver`, not hard-coded by
the table. Tests use an explicit fixture. Production resolution stays unavailable until LG-011 is
approved.

### Identity Action Secret

Table: `identity_action_secrets`.

One immutable issuance plus one-way lifecycle evidence for the `EMAIL_VERIFICATION` purpose.

| Field | Type | Constraints |
|---|---|---|
| `id` | UUID | Primary key. |
| `account_id` | UUID | Required FK to `accounts`. |
| `purpose` | text | `EMAIL_VERIFICATION` in S1B1. |
| `secret_digest` | bytea | Required, exactly 32 bytes, globally unique; raw bearer is never stored here. |
| `issued_at` | timestamptz | Database time. |
| `expires_at` | timestamptz | Required and later than `issued_at`. |
| `consumed_at` | timestamptz | Null until successful activation; once set, immutable. |
| `superseded_at` | timestamptz | Null until eligible resend; once set, immutable. |
| `superseded_by_id` | UUID | Nullable self-FK; present exactly when `superseded_at` is present. |
| `attempt_count` | integer | Nonnegative bounded counter for admitted pre-terminal attempts. |
| `first_attempt_at` | timestamptz | Null iff count is zero. |
| `last_attempt_at` | timestamptz | Null iff count is zero; not before first attempt. |
| `created_at` | timestamptz | Database time, equal to the issuance fact for ordering purposes. |

Constraints/indexes:

- `CHECK octet_length(secret_digest) = 32`;
- consumed and superseded are mutually exclusive terminal states;
- terminal timestamps are not before issuance;
- partial unique index on `(account_id, purpose)` where both terminal timestamps are null;
- lookup index on `(secret_digest, purpose)`;
- expiry index for live records;
- trigger prevents mutation of identity, subject, purpose, digest, and issue/expiry facts; terminal
  fields move only null→value, and attempt evidence only accumulates before terminal state.

Raw bearer format:

- 32 CSPRNG bytes;
- URL-safe Base64 without padding for transport;
- SHA-256 digest for lookup;
- constant-time comparison after indexed candidate resolution.

### Identity Security Event

Table: `identity_security_events`.

Append-only evidence for Identity events that are not privileged Admin Audit rows.

| Field | Type | Constraints |
|---|---|---|
| `id` | UUID | Stable primary key. |
| `occurred_at` | timestamptz | Required database time. |
| `event_type` | text | Closed S1B1 set: `BOOTSTRAP_ADMIN_CREATED`, `STUDENT_REGISTRATION_ACCEPTED`, `EMAIL_VERIFICATION_REISSUED`, `STUDENT_EMAIL_VERIFIED`. |
| `account_id` | UUID | Nullable FK for migration/backfill edge cases; present for new S1B1 events. |
| `action_secret_id` | UUID | Nullable FK when the event concerns one issuance/consumption. |
| `account_revision` | integer | Positive when present. |
| `request_id` | text | Required for HTTP events; deployment operation correlation for bootstrap. |
| `evidence` | jsonb object | Safe, schema-versioned metadata only. |

The evidence object may carry policy ID, event schema version, outcome class, and locale. It never
contains email, password/hash, bearer/digest, identifier HMAC, provider payload, client IP, or
protected link. UPDATE/DELETE is rejected by trigger. A hidden registration/resend no-op creates no
Account-linked event.

### Outbox Event

Table: `outbox_events`.

Immutable source intent. S1B1 creates `identity.email_verification_requested` schema version 1.

| Field | Type | Constraints |
|---|---|---|
| `id` | UUID | Stable event and logical delivery-operation ID. |
| `event_type` | text | Required dotted lower-case identifier. |
| `schema_version` | integer | Positive; `1` for S1B1. |
| `source_module` | text | `IDENTITY_AND_ACCESS`. |
| `aggregate_type` | text | `ACCOUNT`. |
| `aggregate_id` | UUID | Account ID. |
| `aggregate_revision` | integer | Positive Account revision at emission. |
| `safe_payload` | jsonb object | Action-secret ID, purpose, locale, template contract version, expiry, and policy-safe source references; no address or bearer. |
| `occurred_at` | timestamptz | Database time. |
| `available_at` | timestamptz | Not before occurrence. |
| `correlation_id` | text | Safe request ID. |

Indexes support `(available_at, occurred_at)`, aggregate history, and event type. Event identity and
payload are immutable. S9 may add delivery/lease/attempt/receipt tables, but it must not rewrite this
source fact.

### Outbox Protected Payload

Table: `outbox_protected_payloads`.

One-to-one protected delivery material for an outbox event.

| Field | Type | Constraints |
|---|---|---|
| `event_id` | UUID | Primary key and FK to `outbox_events`. |
| `key_version` | text | Required bounded secret-manager key reference/version, never key material. |
| `nonce` | bytea | Required length for the selected authenticated-encryption algorithm; unique with key version. |
| `ciphertext` | bytea | Required nonempty authenticated ciphertext. |
| `created_at` | timestamptz | Database time. |

The plaintext before encryption contains only the minimum delivery snapshot: correspondence
destination, locale, template-contract version, verification bearer, and expiry. It never enters
ordinary JSON, logs, Audit, security events, error text, or browser persistence. The encryption
adapter is required for eligible registration/resend; missing configuration or encryption failure
rolls back the whole source transaction.

## Non-relational models

### Current Policy Set

Typed resolver output, not authoritative table state in S1B1:

```text
PolicySet
  id
  display_locale
  items[]
    kind
    version
    public_url
    label
```

The public read exposes safe display fields only. Registration resolves the submitted set ID again
and accepts exactly its required items. Production has no usable set until LG-011 exit evidence is
configured.

### Anonymous Browser Security State

No database entity. A signed opaque host-only cookie contains a random anonymous ID plus key version
and MAC. A separate secret derives/verifies the browser-memory CSRF token bound to that anonymous
ID. Cookie and CSRF keys are distinct, rotated secret references. The state grants no Account or
capability and is used only for Origin/CSRF admission and a privacy-safe limiter dimension.

### Rate-Limit Entry

Redis/local fallback value:

```text
policy_version + opaque_dimension_key
  algorithm state
  expiry
```

Opaque dimension keys are HMACs under a dedicated versioned secret. Inputs may be endpoint,
normalized bounded identifier, trusted client network, anonymous ID, or global scope. Redis loss
cannot erase business state. Local fallback is memory/key-bounded, shorter-lived, and stricter than
the distributed development/test fixture.

## Command transactions and lock order

### Register Student

Pre-transaction:

1. validate strict request shape, Origin/CSRF, and limiter decision;
2. normalize/validate email and display name;
3. resolve the current policy set and validate submitted acceptance;
4. screen password and produce its Argon2id hash;
5. generate bearer/digest, event IDs, and protected ciphertext in memory.

Transaction:

1. insert Account as `STUDENT/PENDING_VERIFICATION`, preserving correspondence email;
2. on normalized-email uniqueness conflict, roll back/exit as a hidden no-op;
3. insert credential;
4. insert every required policy acceptance;
5. insert action-secret digest;
6. insert registration security event;
7. insert outbox event and protected payload;
8. commit.

Any failure returns no session, token, delivery claim, or partial row.

### Request Verification

After uniform structural/CSRF/limiter/delivery-admission checks:

1. begin transaction;
2. resolve and lock eligible Account;
3. if absent/ineligible, end as hidden no-op;
4. lock current live action secret;
5. insert replacement secret;
6. mark prior secret superseded and link replacement;
7. append security event, outbox event, and protected payload;
8. commit.

Lock order is Account → action secret. Every hidden outcome maps to the same `202`.

### Consume Verification

1. digest the body-submitted bearer and resolve its immutable Account ID;
2. begin transaction;
3. lock Account;
4. lock exact action secret;
5. recheck purpose, digest, expiry, terminal fields, role, and Account status;
6. update the pending Student to Active, set `email_verified_at`, increment revision;
7. mark the secret consumed;
8. append `STUDENT_EMAIL_VERIFIED`;
9. commit.

Lock order is Account → action secret, matching resend. Exactly one concurrent transaction
activates; every loser returns `TOKEN_INVALID` without another state mutation.

## Validation and retention rules

- Retain append-only evidence and outbox intent; no deletion job is activated while LG-003 is open.
- Database constraints supplement, not replace, command validation and safe public errors.
- Text/JSON-column leakage tests scan for password and bearer canaries after success, duplicate,
  rollback, resend, and consumption.
- Production activation requires the open policy, email, operating-envelope, and
  compromised-password gates at their named boundaries; the schema itself resolves none of them.

Governing rules: BR-001, BR-002, BR-003, BR-008, BR-105, BR-120, and BR-122.
